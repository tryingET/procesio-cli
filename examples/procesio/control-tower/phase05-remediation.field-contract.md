# PROCESIO Control Tower v1 — Phase 05 remediation contract

This contract repairs the two evidence-backed Phase 05 gaps without weakening the
original acceptance gate. It is a separately approved amendment to the field run,
not a retroactive claim that the first Phase 05 attempt passed.

## Why remediation is required

The original Phase 05 report completed substantial useful work, but correctly did
not satisfy the original all-core-features acceptance contract:

1. **form-sync-result-rendering** — the published form launched Ingest Evidence and
   wrote the row, but the runtime's native synchronous result writer did not receive
   the `content.variable`-compatible envelope it expects, so decision and next action
   were not populated automatically from the real submit response;
2. **webhook-field-mapping** — the webhook lifecycle was safe and fully cleaned up,
   but PROCESIO binds a webhook body as one generated model object. Mapping individual
   body fields directly into multiple primitive process inputs produced a never-started
   instance and no `INVESTIGATE_GATE` ledger row.

The original coordinator was correct to reject `passed_with_gap` for Phase 05.
Only the connector fallback in Phase 03 is allowed to remain a final project gap.
This remediation must resolve both Phase 05 outcomes or leave Phase 05 blocked.

# Stage 05R-1 — native form-result contract

**Authorized mutations:** edit Ingest Evidence and Mission Control only.
**Execution budget:** one form submission; at most two resulting process instances
(the Ingest instance and its awaited Normalizer child).

## Inspect and preserve compatibility

1. Re-fetch Ingest Evidence and Mission Control by stable ID. Save complete before
   snapshots and digests under `remediation/phase05/backups/`.
2. Inspect the live form `RUN_PROCESS` event, process input/output variable IDs,
   outputMap rows, one successful standard process instance's variable array, and the
   SPA writer path that consumes synchronous launch responses.
3. Prove the existing CLI/subprocess contract that must remain compatible:
   - all current Ingest inputs remain accepted;
   - all current process outputs remain present and keep their IDs where the platform
     permits stable IDs;
   - Repository Pulse and Mission Control mappings are not silently orphaned;
   - token denial, invalid-JSON denial, idempotent upsert, and direct CLI/subprocess
     output semantics remain intact.

## Repair

4. Make the smallest process change that gives the form writer the shape it actually
   consumes. The preferred contract is a custom-response envelope containing:
   - a `variable` collection in the exact live variable-instance shape expected by the
     form's outputMap writer; and
   - the existing structured response under a stable member such as `response`, so
     direct callers do not lose the current decision/summary/next-action object.
5. Build that envelope deterministically from the existing output variables. Bind any
   added Node Error output and set a nonzero Timeout.
6. Point the process customResponse at the envelope variable. Do not replace or remove
   the existing `response` process output.
7. Adjust the form outputMap only where live evidence shows it is wrong. Do not embed
   the access token or add an autonomous trigger.
8. Dry-run/preview where supported, require clean backend and designer validation,
   write each edited resource once, and re-fetch it.

## Prove

9. In a real browser, open the published tiny URL with a clean context and capture
   pre-interaction console/network diagnostics.
10. Use the launcher-provided `form_evidence_key`, the valid token from the 0600 file,
    and a paused/resumable status payload. Submit **exactly once**.
11. Do not invoke the SPA writer manually, patch the DOM, replay the request, or use a
    previously completed instance as substitute evidence.
12. Prove from the real submit response that the native form event automatically shows:
    - decision `RESUME_CHECKPOINT`;
    - a non-empty next action;
    - summary/severity and duplicate/update state;
    - no controlled error.
13. Reconcile the exact process instance and ledger row. Prove one row for the key and
    no duplicate key. Capture masked screenshots and browser diagnostics.
14. Re-fetch and validate/audit Ingest and the form after the run.

# Stage 05R-2 — whole-body webhook adapter and complete cleanup

**Authorized temporary mutations:** one webhook and at most one adapter process.
**Execution budget:** one webhook launch; at most three resulting process instances
(the adapter, its awaited Ingest child, and the Ingest process's Normalizer child).

The live platform evidence established that a webhook supplies one generated model
object, not arbitrary per-field primitive bindings. The remediation therefore uses
the platform-native whole-body architecture rather than repeating the failed mapping.

## Architecture

1. Confirm zero exact-title `CLI Control Tower - Intake Drill` webhooks and zero
   exact-title `CLI Control Tower - Intake Drill Adapter` processes before creation.
2. Create the temporary webhook from a representative body containing all ingest
   fields. Capture its generated webhook model and attribute IDs.
3. Preferred implementation: create one temporary adapter process named
   `CLI Control Tower - Intake Drill Adapter` with one required input typed to the
   generated webhook body model. Extract each attribute deterministically into plain
   process variables, then synchronously Call Subprocess to Ingest Evidence using the
   existing stable process ID and plain-variable mappings.
4. A direct temporary model-typed input on Ingest is allowed only when it is demonstrably
   smaller and can be removed/restored safely. Save a before snapshot and prove final
   restoration. Do not leave a dependency on the temporary webhook model.
5. The adapter or temporary direct path must expose controlled errors and bind every
   Node scripting Error output with a nonzero Timeout.

## Prove

6. Build/validate before create or edit. Re-fetch and require backend/designer validity.
7. Attach the webhook using the whole-body model binding supported by the platform.
8. Launch it exactly once with the launcher-provided `webhook_evidence_key`, valid
   token, and a blocked status expected to normalize to `INVESTIGATE_GATE`.
9. Reconcile the asynchronous webhook instance by stable IDs, exact evidence key, and
   launch window. Do not resend.
10. Prove the adapter/direct process and awaited Ingest child finish successfully,
    output `INVESTIGATE_GATE`, and write exactly one ledger row for the key.
11. Detach the webhook, revalidate/audit every edited retained process, delete the
    webhook, delete the temporary adapter, and prove the generated webhook model is
    gone or unreferenced.
12. Prove final exact-title counts: zero temporary webhooks, zero temporary adapters,
    five retained processes total, one retained Mission Control form, and no public
    anonymous write endpoint from the drill.

Required checks:

- `temporary_titles_absent_before_create`
- `webhook_model_and_attributes_resolved`
- `whole_body_model_binding_used`
- `adapter_calls_ingest_with_plain_variables`
- `temporary_path_backend_and_designer_valid`
- `one_webhook_launch_only`
- `webhook_instance_reconciled`
- `ingest_child_finished`
- `webhook_decision_investigate_gate`
- `webhook_ledger_row_unique`
- `webhook_detached_and_deleted`
- `temporary_adapter_deleted_or_not_used`
- `temporary_webhook_model_removed_or_unreferenced`
